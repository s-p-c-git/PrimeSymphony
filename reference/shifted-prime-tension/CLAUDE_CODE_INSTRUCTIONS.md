# Claude Code Instructions — Updating PrimeSymphony

This file contains ready-to-paste prompts for **Claude Code** to integrate the
`shifted-prime-tension/` bundle into your existing PrimeSymphony repository,
verify everything runs, and commit cleanly.

## Before you start

1. Install Claude Code (needs Node.js):
   ```bash
   npm install -g @anthropic-ai/claude-code
   ```
2. Clone your repo and drop this `shifted-prime-tension/` directory into its root:
   ```bash
   git clone https://github.com/s-p-c-git/PrimeSymphony.git
   cd PrimeSymphony
   # copy the shifted-prime-tension/ folder from this bundle into here
   ```
3. Launch Claude Code in the repo root:
   ```bash
   claude
   ```

Then paste the prompts below in order. Review Claude Code's actions at each step;
approve before it pushes.

---

## Prompt 1 — Orient and inspect

```
I've added a new directory `shifted-prime-tension/` to this repo. Read its
README.md and MANIFEST.md, list the Python scripts in src/, and give me a short
summary of what the subproject does and how it fits alongside the existing
PrimeSymphony content. Don't change anything yet.
```

## Prompt 2 — Verify the environment and run everything

```
Set up a virtual environment for shifted-prime-tension and install its
requirements.txt. Then run each script in src/ in the documented order (step0
through step5). Report for each: whether it completed without error, and whether
its output matches the expected values in the README (e.g. pi(10^7)=664,579;
winding numbers 26.00000 and 44.00000; delta near 0.51). Fix any environment or
import issues you hit, but do not change the mathematical logic. Summarise what
passed.
```

## Prompt 3 — Tidy and lint (optional but recommended)

```
Review the scripts in shifted-prime-tension/src/ for consistency: ensure each
has a module docstring stating what it computes and which paper result it
supports, consistent import ordering, and no dead code or unused imports. Make
only cosmetic/safe changes — do not alter any numerical computation or its
output. Show me a diff of what you changed before saving.
```

## Prompt 4 — Wire into the top-level repo

```
Look at the top-level README of PrimeSymphony. Add a short section linking to
the new shifted-prime-tension/ subproject with a one-paragraph description and a
pointer to its own README. If there's a top-level requirements file or project
index, update it to mention the new dependencies (sympy, mpmath) without breaking
existing entries. Show me the diff first.
```

## Prompt 5 — Stage, review, commit (you approve before push)

```
Stage the shifted-prime-tension/ directory and any top-level README changes.
Write a clear, conventional commit message summarising the addition: the
classification scripts, FFT spectral verification, the rigorous Turing's-method
box, the MCMC density fit, and the Newton pipeline. Show me the full diff and the
proposed commit message. Do NOT commit or push yet — wait for my explicit go-ahead.
```

After you've reviewed:

```
Looks good. Commit and push to origin.
```

---

## Prompt 6 (later) — Add the LaTeX paper

When you have the paper text ready:

```
Create shifted-prime-tension/paper/main.tex using the article document class
with amsmath, amssymb, amsthm, booktabs, hyperref, and graphicx. Set up theorem,
lemma, corollary, remark, and definition environments. I'll paste the paper
content section by section; after each, check that the document still compiles
with pdflatex and report any errors. Reference the figures from ../figures/.
```

## Prompt 7 (later) — Prepare arXiv submission

```
Create a self-contained arXiv submission folder shifted-prime-tension/arxiv/
containing main.tex, the figure files it needs (copied from ../figures/), and a
bbl or embedded bibliography. Confirm it compiles standalone with pdflatex in
that folder, since arXiv compiles from a flat submission. Flag anything arXiv's
build is likely to reject.
```

## Notes / guardrails

- **You stay responsible for what's public.** Always review Claude Code's diff
  before allowing a commit or push — this repo is a profile asset.
- The `data/` directory is regenerated by the scripts. Consider adding it to
  `.gitignore` rather than committing the large `.npy` files:
  ```
  shifted-prime-tension/data/
  ```
  (Ask Claude Code: "Add shifted-prime-tension/data/ to .gitignore so the large
  generated arrays aren't committed.")
- Figures in `figures/` are small and worth committing so the repo renders
  results without requiring a run.
- If Claude Code proposes changing any numerical constant, threshold, or
  mathematical step, decline — those were verified at packaging time.
